# NIST SP 800-53 Rev. 5 Moderate — application responsibility matrix

**Planning worksheet, not an assessed compliance statement.** Impact level,
baseline selection/tailoring, organization-defined parameters (ODPs), applicability,
assessment methods, implementation owner and approval are all **TBD**. Moderate
is not a determination of this system's impact or DoD hosting impact level.

## Baseline scope and reproducibility

This table includes **every control and enhancement selected in AC, AU, CM, IA,
SC, SI, SA, SR, RA and CA** by NIST's Rev. 5 Moderate OSCAL profile, content
version **5.2.0**, pinned to repository commit
`5006f18c8047643eaa70e35dd0d20a58bcc41856`:
[official profile](https://github.com/usnistgov/oscal-content/blob/5006f18c8047643eaa70e35dd0d20a58bcc41856/nist.gov/SP800-53/rev5/json/NIST_SP-800-53_rev5_MODERATE-baseline_profile.json)
and [control catalog](https://github.com/usnistgov/oscal-content/blob/5006f18c8047643eaa70e35dd0d20a58bcc41856/nist.gov/SP800-53/rev5/json/NIST_SP-800-53_rev5_catalog.json).
IDs use conventional parenthetical enhancement notation (OSCAL `ac-2.1` =
AC-2(1)). Families outside this application worksheet are not excluded from the
program baseline; obtain their platform/program assessments separately. No
control has been silently tailored out because an app lacks a feature.

## Status interpretation

* **app-implemented:** a concrete application contribution is present; its file
  evidence is cited. This is not a conclusion that every control clause or ODP
  is satisfied in the operational system.
* **inherited from UDS Core/platform:** proposed external responsibility, **not
  verified inheritance**. Obtain the named provider's authorization/evidence,
  actual settings, shared responsibilities and coverage before crediting it.
* **hybrid:** app artifacts contribute but organizational/platform implementation
  or verification is necessary. Linked capability does not by itself implement
  every listed enhancement (e.g. a scanner does not automatically remediate).
* **TBD:** repository evidence does not establish implementation/applicability;
  program/platform owner must decide and provide evidence. This is not N/A.

Shared bearer tokens do not establish individual identity/MFA; optional PIV is
not default UDS SSO. FIPS validation, at-rest encryption, centralized audit,
independent assessment and an AO decision remain unproven. See [POA&M](POAM.md).
All statuses require operational validation; control effectiveness is **TBD**.
